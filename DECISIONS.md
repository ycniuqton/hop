# Decisions

Choices made where the spec is silent or where it had to be adapted. Newest last.

1. **Module path** is `github.com/ycniuqton/hop`, matching the GitHub repo. Go version is `1.26`, the minimum required by the current `golang.org/x/term` and `golang.org/x/sys`; CI and releases read it from `go.mod`.
2. **Command stubs (M1)** lived in `internal/cli/stubs.go` as data. Every command has since moved to its own handler file (`init.go`, `push.go`, …) and the stubs file is gone.
3. **Usage errors.** Any error not produced by a command handler (unknown command, bad flag, wrong argument count) exits with code 2. Handler errors without an explicit code exit with 1.
4. **`hop completion`** is our own command (Cobra's default `completion` command is replaced) so that `completion install` can be added in M6.
5. **Devlens coding rules in Go.** "Classes" are structs with methods; "base classes" are interfaces; managers live in `internal/workspace`. See `docs/systems/file-transfer/00000-init/02-design.md` §9.
6. **Domain error package `internal/apperr`** (not listed in spec §8 layout) holds `ExitCode` and the user-facing `Error` type shared by all packages.
7. **`internal/naming`** (not in spec §8 layout) owns device-name and hot-name rules, because `target`, `workspace` and `init` all need them and `target` must not import `workspace`.
8. **Upload library.** `feature/s3/manager` (named by the spec) is marked deprecated upstream in favour of `feature/s3/transfermanager`, which is still pre-1.0 (v0.4.x). v1 keeps `manager`, which is stable; revisit once transfermanager reaches 1.0.
9. **Custom endpoint ⇒ path-style addressing.** When `endpoint` is set (MinIO in tests today, S3-compatible providers later) the S3 client uses path-style URLs. The spec lists a path-style flag as future work; this default is the simplest behaviour that makes MinIO work.
10. **Storage errors** are `*apperr.Error` values (exit code + message as in spec §10) that also wrap the sentinels (`ErrNotFound`, `ErrPreconditionFailed`, plus `ErrAccessDenied` and `ErrNetwork`, which the spec does not list). Callers can use `errors.Is` and still get the right exit code.
11. **Storage manager.** `store.Manager` selects the backend (`s3` default, `memory` for tests) from `Settings.Backend`, following Devlens rules 14/15. Only the `s3` backend is user-facing in v1.
12. **Storage contract tests.** `internal/store/storetest` is one behavior suite run against the fake, against the real S3 client over `gofakes3` (test-only dependency, in-process, no Docker), and later against MinIO. gofakes3 lacks conditional writes, so that one case is skipped in the store suite; the CLI tests put a small `If-None-Match: *` shim in front of gofakes3 so the duplicate-name path still runs through the real client.
13. **Copy-source encoding** percent-encodes every key segment, including `+`. Without this, server-side copy of keys containing `+` failed (found by the gofakes3 contract run).
14. **Config adds `workspace_id`.** The completion cache path is `~/.cache/hop/<workspace_id>/` (spec §7), so every device needs the id locally without an S3 call. `init` and `join` write it.
15. **Storage interface additions:** `Download` (parallel ranged GETs through `manager.Downloader`, as spec §8 asks), `CheckBucket` (HeadBucket for init/join verification) and `CanListAllBuckets` (the ListBuckets warning in spec §9).
16. **`store.Manager.UseDefault`** changes the backend used when `Settings.Backend` is empty. Only tests call it (to point at the in-memory fake); config files never name a backend.
17. **`init --endpoint`** is a flag, not just a config field, so MinIO and other S3-compatible servers can be set up without editing JSON. The help text marks it as advanced.
18. **`init` refuses an existing config** (exit 4, "already configured") instead of silently replacing local credentials. Use `join --force` to switch workspaces.
19. **`remove` refuses to remove the current device** (exit 2) with a hint to run it from another device, because the device would lose its own record mid-command.
20. **`mv` and `keep` accept `-f`** with the same meaning as `cp -f`, because both write store objects and the store never overwrites silently.
21. **Success marker.** Lines confirming a finished action start with `✔` when stdout is a color terminal, and with `ok:` otherwise (`--no-color`, `NO_COLOR`, or a pipe). Treating a pipe as "no color" keeps script output plain ASCII.
22. **Bash colon test runs on the host,** not in a Docker image: the Go test builds the binary, sources `/usr/share/bash-completion/bash_completion` and the generated script, and calls `__start_hop` with bash's own word split (`hop ls @web-1 : ba`). It skips when bash-completion is missing; CI installs it. Cobra's V2 bash script already strips the part before the last `:` from each candidate (`__hop_handle_special_char`, the same job as `__ltrim_colon_completions`), so no patch to the script was needed; the test guards that behaviour.
23. **Release archives** are named `hop_<os>_<arch>.tar.gz` without the version, so `install.sh` can use GitHub's `releases/latest/download/` URL with no API call. `install.sh` verifies `checksums.txt` and accepts `HOP_VERSION`, `HOP_INSTALL_DIR`, `HOP_REPO` and `HOP_DOWNLOAD_URL`. Root (for example `| sudo sh`) installs to `/usr/local/bin`, everyone else to `~/.local/bin`. Intel Macs are not a release target (spec §8), so the installer points them to `go install`.
24. **MinIO integration test** (`test/`, build tag `integration`) uses testcontainers-go v0.39 with the generic container API. The official `minio/minio` image is no longer pullable from Docker Hub, so it pins `bitnamilegacy/minio:2025.7.23` (MinIO RELEASE.2025-07-23, which supports conditional writes). It drives the real `bin/hop` binary (override with `HOP_BIN`), skips when Docker is unavailable, and runs against any existing S3-compatible server when `HOP_S3_ENDPOINT` is set.
25. **Storage providers (00001).** `store.Providers` is a registry of `Provider` records (Bizfly Cloud, Amazon S3, Other S3-compatible). The record's fields — fixed endpoint, fixed region, whether to ask for an endpoint, prompt labels — drive `hop init`, so adding a provider is one entry and `init` has no per-provider branches. Bizfly Cloud is listed first and is the default answer, as requested. Its endpoint is `https://hcm.ss.bfcplatform.vn` and its region is `us-east-1` (Bizfly ignores the region, but SigV4 needs one).
26. **The provider is not stored.** It is derived from `endpoint` (`FromEndpoint`), so `config.json` and the `hop1:` join code are unchanged, and devices that join or were configured before 00001 report their provider correctly.
27. **Without a TTY, `init` keeps its old default (Amazon S3),** or "Other" when `--endpoint` is given. Only interactive runs default to Bizfly Cloud, so existing scripts behave exactly as before.
28. **`--url`** accepts virtual-hosted (`https://bucket.host`) and path-style (`https://host/bucket`) bucket URLs. A host that matches no known provider becomes provider `s3` with that endpoint. The bucket prompt for Bizfly accepts either a URL or a plain name. A typed endpoint without a scheme gets `https://`.
29. **CopyObject fallback.** A `501 NotImplemented` maps to the new sentinel `store.ErrNotSupported`. `Copy` then switches to the existing multipart `UploadPartCopy` path and remembers the gap for the rest of the process. Empty objects are rewritten empty with their metadata, because multipart copy needs at least one byte. Verified live on Bizfly, and in tests with a gofakes3 shim that answers CopyObject with 501 and emulates UploadPartCopy.
30. **Custom endpoints use `ResponseChecksumValidation = WhenRequired`.** Bizfly returns no checksum headers, and the SDK printed a `DEBUG Response has no supported checksum` line on every GET. AWS keeps the SDK defaults.
31. **Secret prompts never show the default.** A secret taken from the environment is shown as `[from environment]` on every input path. Before, the non-`*os.File` fallback printed the value.
32. **Arrow-key menu.** On a real terminal, `Console.Choose` is a menu: ↑/↓ or j/k move, Enter selects, digits jump straight to an item, Ctrl-C cancels (exit 130). It needs no new dependency: `x/term` raw mode and ANSI redraw, with keys read one byte at a time so typed-ahead input survives. Piped input and tests keep the numbered `Choose [n]:` list, and without a TTY the default is used.
33. **Agent support (00002).** Secrets never go on the command line: `HOP_ACCESS_KEY` / `HOP_SECRET_KEY` (preferred over `AWS_*`, since `AWS_` is misleading on Bizfly) or `--secret-stdin`. There are no `--access-key` / `--secret-key` flags, because argv shows up in shell history and `ps`.
34. **JSON errors go to stderr,** so stdout keeps exactly one document on success and stays empty on failure. The object is `{"error","hint","code","kind"}`, where `kind` is a stable name per exit code (`apperr.ExitCode.Kind`). `--json` is also detected in the raw arguments, because a bad flag stops Cobra before it reads `--json`.
35. **Action results.** Every action command reports through `Console.Done` / `Console.Report` with an `Outcome{Action, Data}`. Text mode prints the same `✔` line as before, and `--json` prints one object with an `action` field. `push` of several files reports one object with a `files` array. With `--json`, init/join skip the completion offer, and warnings that text mode prints to stderr appear in the object (`remove` → `warning`, `init` → `keys_too_broad`).
36. **The skill is embedded** (`internal/skill/SKILL.md`, `go:embed`), so `hop skill install` always writes guidance that matches the installed binary. Installing writes atomically and rewrites the same bytes. The user scope is `$CLAUDE_CONFIG_DIR` or `~/.claude`; the project scope is `./.claude`. `hop skill print` drops the front matter for `AGENTS.md`. A test checks every `hop <command>` and `--flag` the skill mentions against the command tree, and another runs its recipes.
37. **Not done in 00002:** an npm package and an MCP server (`hop mcp`). Agents that can run a shell are served by the CLI plus the skill; an MCP server is the next step for agents without a shell.
38. **`hop update` reads the latest tag from the `/releases/latest` redirect** instead of the GitHub API, so it never hits the 60-requests/hour anonymous limit. It downloads the same archive and `checksums.txt` as `install.sh`, refuses a checksum mismatch, and renames the new binary over the real file (symlinks resolved), so it stays where the user installed it. Version order is numeric `x.y.z`, a `-dev` build sorts before its release, and a plain `dev` build sorts before everything. A build newer than the latest release is left alone unless `--force` is given. `--version` pins a tag and always installs it.
39. **`hop update` does not rewrite the skill itself.** The running process still embeds the old skill, so it prints a reminder to run `hop skill install` with the new binary.
40. **`hop uninstall` removes the whole local footprint by default, config included.** Leaving keys behind on an uninstalled machine is the riskier default. It lists everything first, needs confirmation (or `-y`), and `--keep-config` opts out. It cannot drop the device from the workspace, because `remove` refuses to remove the current device, so it names the `hop remove` command to run elsewhere. Empty `hop` folders (`~/.config/hop`, `~/.claude/skills/hop`) are removed too.
41. **Release source overrides:** `HOP_RELEASE_BASE` (default `https://github.com`) and `HOP_REPO` (default `ycniuqton/hop`), matching `install.sh`, for mirrors and tests. `Env.Executable` lets tests aim update and uninstall at a temp file instead of the test binary.
42. **Windows (00003).** Platform differences sit behind `_windows.go` / `_unix.go` build tags in six places:
    - the detached refresh spawn;
    - the config mode check (Unix-only, since Windows modes do not describe ACLs);
    - binary swap and delete;
    - console virtual-terminal mode;
    - the default completion shell;
    - the update permission hint.
    Business code never checks `runtime.GOOS`; only tests do, to skip Unix-mode and symlink checks.
43. **Self-update and uninstall of a running `hop.exe`.** Windows lets a running executable be renamed but not overwritten or deleted. `update` moves `hop.exe` to `hop.exe.old`, renames the new file in, and rolls back if that fails. Every start runs `CleanStale` to delete a leftover `.old`. `uninstall` moves the binary aside and starts a detached, hidden `cmd /c` that deletes it about two seconds after hop exits. CI checks both on `windows-latest` with a real running binary.
44. **Release packaging is a registry** (`selfinstall.PackagingFor`): Windows uses `.zip` + `hop.exe`, everything else `.tar.gz` + `hop`, matching GoReleaser's `format_overrides`.
45. **`install.ps1`** mirrors `install.sh`:
    - it accepts `HOP_VERSION`, `HOP_INSTALL_DIR`, `HOP_REPO` and `HOP_DOWNLOAD_URL`, and verifies `checksums.txt`;
    - it installs to `%LOCALAPPDATA%\Programs\hop` and adds that folder to the user PATH;
    - errors use `throw`, never `exit`, because `exit` would close the user's window under `irm | iex`.
    It was tested under PowerShell 7 on Linux up to the step that runs `hop.exe`; CI runs it end to end on Windows.
46. **PowerShell completion** is installed to `%LOCALAPPDATA%\hop\completion.ps1` (`home\AppData\Local\hop`). hop prints the line to dot-source it from `$PROFILE` rather than editing the profile, because its location varies (OneDrive redirection, Windows PowerShell vs PowerShell 7). `pwsh` and `powershell.exe` are aliases of `powershell`, and with `$SHELL` unset Windows defaults to PowerShell.
47. **The `@` notation stays.** PowerShell needs `@…` arguments quoted, which hop cannot change. The README documents it, and Cobra's PowerShell completion escapes `@`. An alternative prefix was rejected because it would make the `@` rule inconsistent across platforms.
48. **Console colours and the ↑/↓ menu** need `ENABLE_VIRTUAL_TERMINAL_PROCESSING`. If the console refuses it, that stream is treated as non-colour and non-TTY: plain text and the numbered list. `x/term` raw mode already enables VT input, so arrow keys arrive as the same escape sequences as on Unix.
49. **README demos are VHS recordings,** not screen captures. `demo/*.tape` scripts type real hop commands into a real terminal, and `demo/record.sh` runs them against `demo/fakes3`, an in-memory S3 server with conditional writes that denies ListBuckets like a scoped key. Each tape gets a fresh server and fresh machine homes. No real credentials appear, and anyone can regenerate the GIFs with `make demo`. The setup demo picks "Other S3-compatible" because it cannot reach Bizfly; the README says so.
50. **Table alignment on colour terminals.** `Console.Table` laid out the header with its dim escape codes, which `tabwriter` counted as width, so the first column was padded 4 characters too wide. Tables are now laid out plain and the header is dimmed afterwards.
51. **Shared store at `@@:`.** One store tree that belongs to no device, stored at `store/_shared/` and reusing the shared shelf's reserved name, so every store command works without new code paths. The user proposed `@@`. `@shared:` was rejected because it would reserve a name a device might already have, and because PowerShell silently reads `@shared:x` as a scoped variable splat and passes an empty string; `'@@:x'` needs quotes like every `@` argument. `@@` alone is the shared shelf. `hop status` now writes every row in @ notation (`@@`, `@web-1:`) so the shared area is not shown as a bare `@`, which means "this machine".
52. **Store results name the destination, resolved.** `@:` (this machine) and `@@:` (shared) are one character apart, so `cp`, `mv` and `rm` now print where they acted, with `@`/`@me` expanded to the device name (`copied 1 file(s) → @laptop:docs/`), and the `rm` prompt says what it will delete from. JSON gains `to` / `from`. `Target.Ref()` produces the spelling.
53. **Two-machine demos use tmux inside VHS.** VHS records one terminal, so `demo/split.sh` opens tmux with two titled panes (server-1, server-2), each a shell with its own HOME. Tapes switch panes with the tmux prefix, and prefix + J pastes server-1's join code into server-2, like a real copy-paste. One scene per idea (hot, store, `@@:`, setup) replaces the single mixed usage GIF. `hop devices` is kept out of the GIFs because it shows the recording machine's real hostname.
54. **Folder copies nest under a destination folder.** `hop cp -r ./logs @web-1:backups/` gives `@web-1:backups/logs/…`; a destination without a trailing `/` names the copy (`@web-1:logs` → `@web-1:logs/…`). This matches `cp -r` into an existing folder. The README, `cp --help` and skill examples that copied into `…:logs/`, which produced `logs/logs/…`, now copy into `@web-1:`.
