# Decisions

Choices made where the spec is silent or where it had to be adapted. Newest last.

1. **Module path** is `github.com/ycniuqton/hop`, matching the GitHub repo. Go version is `1.26`, the minimum required by the current `golang.org/x/term` and `golang.org/x/sys`; CI and releases read it from `go.mod`.
2. **Command stubs (M1)** lived in `internal/cli/stubs.go` as data. Every command has since moved to its own handler file (`init.go`, `push.go`, …) and the stubs file is gone.
3. **Usage errors.** Any error not produced by a command handler (unknown command, bad flag, wrong argument count) exits with code 2. Handler errors without an explicit code exit with 1.
4. **`hop completion`** is our own command (Cobra's default `completion` command is replaced) so that `completion install` can be added in M6.
5. **Devlens coding rules in Go.** "Classes" are structs with methods; "base classes" are interfaces; managers live in `internal/workspace`. See `docs/systems/file-transfer/00000-init/02-design.md` §9.
6. **Domain error package `internal/apperr`** (not listed in spec §8 layout) holds `ExitCode` and the user-facing `Error` type shared by all packages.
7. **`internal/naming`** (not in spec §8 layout) owns device-name and hot-name rules, because `target`, `workspace` and `init` all need them and `target` must not import `workspace`.
8. **Upload library.** `feature/s3/manager` (named by the spec) is marked deprecated upstream in favour of `feature/s3/transfermanager`, which is still pre-1.0 (v0.4.x). v1 keeps `manager`, which is stable; revisit once transfermanager reaches 1.0.
9. **Custom endpoint ⇒ path-style addressing.** When `endpoint` is set (MinIO in tests today, S3-compatible providers later) the S3 client uses path-style URLs. The spec lists a path-style flag as future work; this default is the simplest behaviour that makes MinIO work.
10. **Storage errors** are `*apperr.Error` values (exit code + message as in spec §10) that also wrap the sentinels (`ErrNotFound`, `ErrPreconditionFailed`, plus `ErrAccessDenied` and `ErrNetwork`, which the spec does not list). Callers can use `errors.Is` and still get the right exit code.
11. **Storage manager.** `store.Manager` selects the backend (`s3` default, `memory` for tests) from `Settings.Backend`, following Devlens rules 14/15. Only the `s3` backend is user-facing in v1.
12. **Storage contract tests.** `internal/store/storetest` is one behavior suite run against the fake, against the real S3 client over `gofakes3` (test-only dependency, in-process, no Docker), and later against MinIO. gofakes3 lacks conditional writes, so that one case is skipped in the store suite; the CLI tests put a small `If-None-Match: *` shim in front of gofakes3 so the duplicate-name path still runs through the real client.
13. **Copy-source encoding** percent-encodes every key segment, including `+`. Without this, server-side copy of keys containing `+` failed (found by the gofakes3 contract run).
14. **Config adds `workspace_id`.** The completion cache path is `~/.cache/hop/<workspace_id>/` (spec §7), so every device needs the id locally without an S3 call. `init` and `join` write it.
15. **Storage interface additions:** `Download` (parallel ranged GETs through `manager.Downloader`, as spec §8 asks), `CheckBucket` (HeadBucket for init/join verification) and `CanListAllBuckets` (the ListBuckets warning in spec §9).
16. **`store.Manager.UseDefault`** changes the backend used when `Settings.Backend` is empty. Only tests call it (to point at the in-memory fake); config files never name a backend.
17. **`init --endpoint`** is a flag, not just a config field, so MinIO and other S3-compatible servers can be set up without editing JSON. The help text marks it as advanced.
18. **`init` refuses an existing config** (exit 4, "already configured") instead of silently replacing local credentials. Use `join --force` to switch workspaces.
19. **`remove` refuses to remove the current device** (exit 2) with a hint to run it from another device, because the device would lose its own record mid-command.
20. **`mv` and `keep` accept `-f`** with the same meaning as `cp -f`, because both write store objects and the store never overwrites silently.
21. **Success marker.** Lines confirming a finished action start with `✔` when stdout is a color terminal, and with `ok:` otherwise (`--no-color`, `NO_COLOR`, or a pipe). Treating a pipe as "no color" keeps script output plain ASCII.
22. **Bash colon test runs on the host,** not in a Docker image: the Go test builds the binary, sources `/usr/share/bash-completion/bash_completion` and the generated script, and calls `__start_hop` with bash's own word split (`hop ls @web-1 : ba`). It skips when bash-completion is missing; CI installs it. Cobra's V2 bash script already strips the part before the last `:` from each candidate (`__hop_handle_special_char`, the same job as `__ltrim_colon_completions`), so no patch to the script was needed; the test guards that behaviour.
23. **Release archives** are named `hop_<os>_<arch>.tar.gz` without the version, so `install.sh` can use GitHub's `releases/latest/download/` URL with no API call. `install.sh` verifies `checksums.txt` and accepts `HOP_VERSION`, `HOP_INSTALL_DIR`, `HOP_REPO` and `HOP_DOWNLOAD_URL`. Root (for example `| sudo sh`) installs to `/usr/local/bin`, everyone else to `~/.local/bin`. Intel Macs are not a release target (spec §8), so the installer points them to `go install`.
24. **MinIO integration test** (`test/`, build tag `integration`) uses testcontainers-go v0.39 with the generic container API. The official `minio/minio` image is no longer pullable from Docker Hub, so it pins `bitnamilegacy/minio:2025.7.23` (MinIO RELEASE.2025-07-23, which supports conditional writes). It drives the real `bin/hop` binary (override with `HOP_BIN`), skips when Docker is unavailable, and runs against any existing S3-compatible server when `HOP_S3_ENDPOINT` is set.
